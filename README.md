# PFclassify

An R package for standardized classification and quantification of red meat and poultry subtypes from dietary data using USDA food codes.

## Overview

**PFclassify** provides tools for:

- Ingredient-level classification through recursive food code decomposition
- Quantification of red meat and poultry by subtype (e.g., beef, pork, chicken)
- Distinction between lean and processed categories
- Reproducible workflows for dietary data analysis

**PFclassify** incorporates analytical results from public avaiable data:

 - USDA food codes (FNDDS): https://www.ars.usda.gov/northeast-area/beltsville-md-bhnrc/beltsville-human-nutrition-research-center/food-surveys-research-group/docs/fndds/
 - Food Patterns Equivalents Ingredient Database (FPID):https://www.ars.usda.gov/northeast-area/beltsville-md-bhnrc/beltsville-human-nutrition-research-center/food-surveys-research-group/docs/fped-overview/


For more details, see the package examples and function documentation.

 - Intake amount (grams)

The `infile` argument accepts the user's dietary intake data as a `data.frame`. The arguments `var_cycle`, `var_Food_code`, and `var_weight` specify the column names corresponding to the survey cycle (`"year"`), USDA food code (`"fdcd"`), and intake amount by weight (`"fdwt"`), respectively. These arguments should be provided as character strings.

The `your_cycle` argument is a character vector specifying how the survey cycles are coded in the input data. In this example, the dataset contains only one survey cycle, coded as `"cycle1314"`, so `your_cycle = c("cycle1314")`.

The `out_cycle` argument is a character vector of the same length as `your_cycle` that provides the standardized cycle codes to replace the original values. Each element should be a four-digit character string (e.g., `"1314"`, `"1516"`, or `"1718"`), corresponding to the USDA food code cycles 2013–2014, 2015–2016, and 2017–2018, respectively. Since the example dataset represents the 2013–2014 survey cycle, use `out_cycle = c("1314")`.

```r
# Format PF_sample_2 store as PF_sample_2_fmt
PF_sample_2_fmt <- ReFormatDF(
  infile = PF_sample_2,
  var_cycle = "year",
  var_Food_code = "fdcd",
  var_weight = "fdwt",
  your_cycle = c("cycle1314"),
  out_cycle = c("1314")
) 
```

### 3. Calculate meat and poultry subtypes

`CalPF` in **PFclassify** calculates user-specified meat and poultry subtypes in user's dietary data.

View documentation of `CalPF`
```r
?CalPF
```
The following example demonstrates how to use `CalPF` with the formatted dataset `PF_sample_2_fmt` generated by `ReFormatDF`.

The `infile` argument accepts a formatted `data.frame` produced by `ReFormatDF`. The `var_id` argument specifies the column name containing the participant identifier (e.g., `"id"`) as a character string.

The `fdcd_description` argument is a logical value. If `TRUE`, the output includes the description of each USDA food code.

The `option_subtotal`, `option_meat`, `option_poult`, and `option_curedmeat` arguments accept character vectors specifying the meat and poultry categories to calculate. Each argument may contain all available options, a subset of the available options, or an empty vector (`c()`) if no calculations are requested for that category.

The available options for each argument are:

- **`option_subtotal`**: `"meat"`, `"poult"`, `"curedmeat"`
- **`option_meat`**: `"beef"`, `"pork"`, `"other"`
- **`option_poult`**: `"chick"`, `"turkey"`, `"other"`
- **`option_curedmeat`**: `"beef"`, `"pork"`, `"chick"`, `"turkey"`, `"other"`

In this example, `CalPF` is used to calculate total processed meat and poultry intake, along with processed pork and processed chicken intake.

```r
# Calculate total processed, processed pork and processed chicken
PF_sample_2_PF_break <- CalPF(
  infile = PF_sample_2_fmt,
  var_id = "id",
  fdcd_description = TRUE,
  option_subtotal = c("curedmeat"),
  option_meat = c(),
  option_poult = c(),
  option_curedmeat = c("pork", "chick")
)
```
### 4. Aggregate results as needed for analysis
`CalPF` calculates the meat and poultry subtype content for each reported food item. The output is provided at the individual food item level and is not aggregated.

Users should perform any subsequent data aggregation according to their specific research objectives. For example, the output can be aggregated to estimate:

- Total intake per participant per day
- Mean intake across multiple recall days
- Population-level average intake
- Intake by food category or survey cycle
- Other summary measures required for downstream analyses

The appropriate aggregation method depends on the study design and analysis goals.
